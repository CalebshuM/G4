# AI 接入包

这是通用 RAG 数据包，尚未连接任何外部 AI 服务，也不包含向量或模型密钥。无需训练模型。

## 方式一：上传文档

将 `knowledge.txt` 上传到支持文档知识库的 AI 应用。将 `system_prompt.txt` 内容复制为该助手的系统指令。平台仍需完成自身的解析、索引和检索配置。不要同时上传逐页原文与本文件，以免重复检索；原文留作核对。

## 方式二：向量数据库或自建 RAG

1. 按 UTF-8 逐行读取 `chunks.jsonl`，每行是一个完整问答条目。
2. 对 `text` 字段生成 embedding，使用 `id` 作为主键，保存 `metadata`。条目已经按语义切分，通常无需再次切分；具体以目标模型长度限制为准。
3. 对用户问题生成同一模型的 embedding，检索若干相关条目，可先取 3–5 条并根据实际效果调整。
4. 将检索结果连同 id、text 和 metadata 作为 `knowledge_context` 传给模型，并使用提供的系统提示词。
5. 输出回答时保留来源页码；无关或证据不足时拒绝猜测。检索分数不能直接视为答案可信度。

字段：`id` 是由问题标题生成的稳定编号；`question` 和 `answer` 可用于 FAQ；`text` 是含主题和来源的完整检索文本；`metadata.pdf_pages` 是包含目录页的 PDF 实际页码；`source_sha256` 标识源文件版本。`related_links` 是同页链接，未与单个问题逐项匹配。`source_published_on` 为空表示来源发布日期未知。

## 本地检索演示

需要 Python 3，仅使用标准库，无需联网。在本目录运行：

```powershell
python search.py "已选课但找不到课程怎么办" --top-k 3
python search.py "小组作业每个人都需要提交吗" --messages
```

第一条输出检索上下文 JSON；第二条输出通用的 role/content 消息数组，可由你的应用适配给所用模型。脚本采用中文双字与英文词的 BM25 词法检索，是可运行的接入示例，不具备向量语义检索能力，也不会自行调用 AI。生产环境应通过真实问题测试召回效果，并按需要接入 embedding、重排和相关性判断。

## 更新与校验

修改上级目录 README.md 后，在上级目录运行 `python build_ai.py`，重新生成数据和清单。生成器校验条目覆盖数、编号唯一性及来源页码。若源 PDF 内容改变，应先重新审阅并更新中文知识库，不能仅更换 PDF 后直接重建。

`manifest.json` 记录条目数、源文件哈希及字段映射。不得将本包当作训练集直接微调：它是带来源的检索资料，没有对话训练或评测标注。
